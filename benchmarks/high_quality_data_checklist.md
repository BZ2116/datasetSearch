# 高质量数据判定清单

高质量判定不能由单一模型分数决定。每个新数据版本至少按以下维度检查，并保留统计结果和失败样本。

| 维度 | 核心问题 | 推荐证据 |
|---|---|---|
| 正确性 | 内容、答案、工具结果是否正确？ | 程序 verifier、规则校验、人工抽检 |
| 完整性 | 输入、标签、轨迹和环境状态是否缺失？ | schema 校验、字段缺失率、轨迹闭合检查 |
| 多样性 | 是否只是重复措辞或重复轨迹？ | exact/near dedup、embedding 聚类、来源分布 |
| 能力覆盖 | 是否覆盖目标任务族和失败模式？ | capability/task-family 分布、coverage 曲线 |
| 可追溯性 | 能否回到原始来源和处理版本？ | provenance 完整率、source ID 可回查率 |
| 安全性 | 是否含违法、隐私、恶意或不适宜内容？ | 安全分类器、PII 检测、人工抽检 |
| 污染风险 | 是否与 dev/test/benchmark 重叠？ | n-gram、URL、语义相似度去污染检查 |
| 可复现性 | 同样输入和配置能否得到同样版本？ | 配置文件、代码版本、随机种子、运行日志 |
| 模型收益 | 在固定预算下是否改善目标能力？ | in-domain、OOD、unseen split、消融实验 |

## 通过条件

- 关键 provenance 字段完整率为 100%；
- schema 和安全检查无阻断性错误；
- 重复、污染和失败样本有明确统计，不以删除后数字掩盖；
- 至少一个未见分布评测不下降，或能解释下降的任务族；
- 数据收益在固定模型、训练步数、token 预算和随机种子下可重复；
- 所有质量阈值、过滤规则和人工抽检协议已版本化。

## 不应单独作为质量证明的指标

- 保留样本数更多；
- 平均长度更长；
- 训练集 loss 更低；
- 单一 benchmark 总分更高；
- LLM judge 单次评分更高。
