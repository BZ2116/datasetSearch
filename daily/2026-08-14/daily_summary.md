
## 二、三张阅读卡片总结

### 1. 数据增强与合成综述

这篇综述的主要贡献不是提出一个新的增强算法，而是建立了一个覆盖 LLM 生命周期的数据合成与增强分类框架。

可以将增强方式分为：

- 语言表达增强：改写、翻译、风格转换；
- 实例增强：实体、数字和场景替换；
- 指令增强：自动生成新的 instruction/task；
- 难度增强：增加约束、步骤和反事实条件；
- 结构增强：组合多个任务，构造多步任务；
- 轨迹增强：增加工具调用、反馈、失败和恢复过程；
- 验证型增强：同时提供答案、过程和可执行 verifier。

关键认识是：合成数据的价值不在于生成了多少条，而在于是否增加了新的表达、实体、任务、难度、推理过程和失败模式。

论文的局限是缺少统一实验，无法直接判断哪种增强方式收益最高。因此后续必须用固定训练预算和未见分布评测验证增强是否真的有效。

### 2. Dolma

Dolma 的核心贡献是公开了大规模预训练数据的来源、处理流程、工具链和数据格式，使“数据集构建过程”本身成为可研究、可复现的对象。

其基本流程是：

```text
Raw Sources
    ↓
Parsing
    ↓
Filtering
    ↓
Deduplication
    ↓
Decontamination
    ↓
Mixing
    ↓
Training / Evaluation
```

Dolma 带来的主要启发：

- 数据来源必须记录 provenance；
- 数据处理规则必须可配置、可复现；
- Filtering 和 Mixing 是不同决策；
- 去重和污染控制不能只看最终样本数；
- 数据集应当具有版本、元数据和处理记录。

因此，高质量数据集不是一个下载好的文件，而是：

```text
数据来源 + 处理规则 + 元数据 + 版本 + 评测协议
```

Dolma 的局限是主要面向英文大规模预训练语料，对 Agent 长任务、工具调用和多步轨迹覆盖不足。

### 3. TRAK

TRAK 研究的是：如何高效估计某个训练样本对模型预测行为的影响。

基本流程是：

```text
训练样本 + 目标预测
    ↓
梯度表示
    ↓
随机投影降维
    ↓
近似 Kernel / 线性建模
    ↓
多个 Checkpoint 聚合
    ↓
训练样本归因分数
```

TRAK 的关键价值是把“哪些数据真正影响模型行为”转化成了可计算的问题，并在 CIFAR、ImageNet、CLIP、QNLI 等任务上验证了方法。

它使用 LDS 等指标，将归因排序与真实子集重训练后的性能变化进行比较，而不是只展示一个主观的 attribution score。

TRAK 对本项目最重要的启发是：

```text
归因分数
    ↓
删除高影响数据
    ↓
重新训练/继续训练
    ↓
观察目标能力变化
```

只有经过这种 counterfactual 验证，才能判断归因结果是否可信。

TRAK 的局限是需要访问模型梯度，归因结果不等于严格因果关系，并且主要验证单点预测，尚未直接解决 Agent 长轨迹归因问题。

## 三、今日四个研究问题的回答

### 问题一：数据增强和合成数据有哪些主要范式？

主要范式包括语言表达、实例、指令、难度、结构、轨迹和验证型增强。

它们解决的问题不同：

| 增强范式 | 主要解决的问题 |
|---|---|
| 语言表达增强 | 避免模型只记忆固定措辞，提升表达泛化 |
| 实例增强 | 扩大实体、数值和场景覆盖 |
| 指令增强 | 缓解人工任务和指令数量不足 |
| 难度增强 | 提升约束处理和复杂推理能力 |
| 结构增强 | 训练任务组合和多步执行能力 |
| 轨迹增强 | 训练工具调用、失败恢复和过程控制 |
| 验证型增强 | 提高答案、过程和标签的可验证性 |

需要警惕：语义漂移、标签失效、任务不可解、重复表达和错误轨迹放大。

### 问题二：高质量数据集需要哪些处理环节？

至少需要：

```text
来源筛选与 provenance
→ 格式解析和 schema 统一
→ 语言/长度/安全/隐私过滤
→ 质量过滤
→ exact/near dedup
→ decontamination
→ 能力覆盖分析
→ 数据选择和混合
→ 版本化管理
→ 固定模型与下游评测
```

高质量不能只由一个质量分数定义，还需要同时考察：

- 正确性；
- 完整性；
- 多样性；
- 任务和能力覆盖；
- 来源可追溯性；
- 重复和污染风险；
- 可复现性。

### 问题三：如何判断数据真正帮助目标能力？

不能只比较数据规模，也不能只看训练集指标。应当采用三层验证：

1. **数据层**：检查正确性、重复率、覆盖度、标签一致性和污染风险；
2. **模型层**：固定模型、训练步数、token 预算和评测集，比较不同数据版本的性能；
3. **因果近似层**：利用归因排序进行删除、重训或反事实验证。

评测必须包含：

```text
训练域
→ 未见表达
→ 未见实体
→ 未见任务模板
→ 未见任务族
→ 跨领域测试
```

只有当合成或筛选数据在固定预算下改善未见分布表现，并且通过质量与一致性检查，才能认为它真正有用。

### 问题四：后续应优先阅读哪些工作？

建议按研究问题推进，而不是继续按论文列表泛读：

1. **数据选择与数据价值**：Data Shapley、FreeShap、Large-Scale Data Selection、Why Less is More、Data Mixture Optimization；
2. **合成数据有效性**：Self-Instruct、Evol-Instruct、FLAN、FLAMES、ToolMind；
3. **来源归因与 provenance**：Source-Aware Training、Approximate Unrolling/Source、DataDignity、Daunce；
4. **评测与 benchmark**：MMLU、GSM8K、BBH、HumanEval/MBPP，以及后续的 WebArena、SWE-bench 和轨迹级 benchmark。

优先级判断标准是：这篇工作能否帮助回答“数据如何构建”“数据操作带来什么收益”“合成数据是否有效”或“模型能力由哪些数据支撑”中的至少一个问题。

## 四、阶段性结论

今天形成了四条阶段性判断：

1. 高质量数据集的核心不是规模，而是来源可追溯、处理可复现、质量可衡量、分布可分析。
2. 过滤、选择、混合和增强是四种不同的数据操作，必须通过对照实验拆分其收益。
3. 合成数据只有在固定预算下提升未见分布能力，并通过质量和 verifier 检查，才算真正有效。
4. 数据归因结果不能直接视为因果结论，必须通过删除、重训或反事实实验验证。

最终研究主线可以暂时概括为：

```text
构建可追溯的数据池
→ 过滤、去重和混合
→ 选择高价值数据
→ 生成可控增强数据
→ 用未见分布和 verifier 验证
→ 用归因方法解释模型能力来源
```

## 五、对最终调研产出的贡献

今日阅读已经为最终四类产出提供了基础：

- **数据构建方法论**：由 Dolma 和综述提供数据生命周期与质量维度；
- **可执行处理 pipeline**：由 Dolma 提供 Filtering、Deduplication、Decontamination、Mixing 的工程骨架；
- **2–3 个可复现小实验**：由综述提出增强对照方向，由 TRAK 提供归因验证范式；
- **benchmark/评测方案**：由 Dolma 的下游评测和 TRAK 的 LDS/删除验证启发，建立数据质量、模型能力、泛化和归因四层指标。
